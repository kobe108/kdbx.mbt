# 功能清单（一次一个功能）

这份清单把 MVP 拆成能独立验收的小功能。每个功能单独提交一次，做完再挑下一个，
避免一次改一大片导致"哪里坏了说不清"。

## 工作节奏

每个功能都按同一套流程走：

1. **先定验收标准**：这一项做完之后，什么命令能证明它是对的。
2. **先写测试向量**：能用官方向量（FIPS、RFC、规范附录）就用官方向量；
   向量用独立实现（Python hashlib 等）核对过再写进测试，不凭记忆手抄。
3. **再写实现**，跑到 `moon test` 全绿。
4. **收尾三连**：`moon fmt`、`moon check`（无警告）、更新本文件与 README 的进度表。
5. **一次提交**，提交信息写清楚"这个功能解决了什么"。

## 现在在哪一步

F1 到 F10 与 F9b 已完成，共 36 个测试用例，`moon check` 无警告。
下一个功能是 **F9b gzip 解压**：KeePass 默认压缩载荷，做完就能看到真正的 XML，
再往后是 F11 条目模型与 F12+ 的 CLI。

### inner header 的一个细节

终止符是**单独一个 `0x00` 字节**，不是一个长度为 0 的字段。第一版实现按字段去读它的
4 字节长度，于是把 XML 的头 4 个字节当成了长度——测试在同一分钟内抓到了这个问题。
这类"少读/多读一个字段"的错误在二进制格式里最常见，所以 fixture 的明文里
特意保留了一段可识别的 XML 前缀用于比对。

### 解密路径的测试数据

`scripts/make_fixture.py` 现在会生成两类数据：271 字节的头部验签 fixture，
以及 519 字节的**完整数据库**（头部、标签、两个 HMAC 块、AES-256-CBC 加密的
inner header 与 XML）。后者的明文由生成器保留在测试里，
所以"Python 加密 → MoonBit 解密"的结果可以被逐字节比对——
两个实现不一致就一定会被抓到，而不是互相印证同一个误解。

### AES-KDF 实测吞吐

轮数是密码库抗暴力破解的代价，也直接决定打开文件要等多久，所以这个数字要测不要猜：

| 构建 | 100 万轮耗时 | 折算吞吐 | 600 万轮（KeePass 常见值） | 6000 万轮（老版本默认档） |
| --- | --- | --- | --- | --- |
| release | 约 1.0 秒 | 约 96 万轮/秒 | 约 6 秒 | 约 63 秒 |
| release（优化前） | 约 2.6 秒 | 约 38 万轮/秒 | 约 16 秒 | 约 2.6 分钟 |
| debug | 约 17 秒 | 约 5.8 万轮/秒 | 约 1.7 分钟 | 约 17 分钟 |

优化做在热点上：原来每轮 `ShiftRows` 先把 16 字节拷进 scratch、再按旋转后的下标写回一遍，
现在改成每行用**一个临时字节原地旋转**，去掉了拷贝和第二遍写回，
于是 `encrypt_in_place` 也不再需要 scratch 参数。百万轮耗时因此减半。
剩余热点是逐字节的下标访问与边界检查，如果还要再快，下一步是 T 表（把 SubBytes、
ShiftRows、MixColumns 合并成 4 次查表），但收益递减，暂时不做。

## 向量来源与核对方式

- F2、F3：KeePass 官方 KDBX 4.1 规范里的字节序列。
- F4、F5：FIPS 180-4（SHA-2 示例）与 RFC 4231（HMAC 测试用例）。
- F6：FIPS-197 附录 B、C 的 AES 示例向量。
- F6 的其余向量：用 .NET 的 AES 实现（ECB、无填充）生成，作为独立参考实现交叉验证；
  S 盒由定义在 Python 中算出（GF(2^8) 求逆加仿射变换），不手抄 256 字节表。
- 教训：S 盒最初只用 5 个抽查值验证，结果漏掉了索引 0x1b 的一个错值，
  直到 FIPS-197 向量失败才暴露。现在测试会**按定义重算全部 256 个格子**逐一比对。
  凡是查表型常量，抽查都不算验证。
- 定位方法：先用 Python 复刻同样的算法结构（[work/aes_check.py](../../work/aes_check.py)），
  它算出的就是标准答案，因此可以确定"算法正确、文件抄错"，
  再用脚本逐格比对（[work/check_sbox.py](../../work/check_sbox.py)）一次定位到错处。
- F7 起：KeePass 与 KeePassXC 的公开测试库文件（按许可证要求不随仓库分发，
  集成测试按固定提交号下载）。
- 所有向量在写进测试前，用 Python 的 `hashlib` / 独立实现交叉核对。
